# SSH 工作区优化规划

- 日期：2026-09-12
- 状态：**设计提案 v0.1，待评审；未实施业务代码**
- 范围：`@miasaki/dsh-ssh` 的页面体验、主题桥接、连接生命周期与必要的安全闭环。
- 配套：[可交互概念稿](preview/2026-09-12-ssh-workspace-concept.html)；数据与终端内容均为本地演示，无网络请求、无真实 SSH。
- 核查口径：本仓源码静态检查。历史测试数量仅作为文档记录，本轮没有运行 SSH 测试或验证真实连接。

## 1. 建议结论

**做一个融入 DSH 的轻量 SSH 工作区，而不是再做一个独立运维后台。**

1. 终端优先：可收起的主机导航 + 多主机终端标签 + 一条紧凑状态栏。
2. 风格统一：一套布局与组件，读取宿主最终生效的语义令牌；三主题不维护三份界面。
3. 渐进呈现：连接、恢复终端、断开是主路径；编辑、信任记录、字体与低频操作进入菜单或抽屉。
4. 自适应依据 **SSH 容器可用宽度**，不是整个桌面窗口宽度；官方右栏展开也必须触发重排。
5. 先修生命周期，再做视觉和功能扩展。界面上的“已连接”必须意味着可以进入并操作终端，而不是一个被禁用的按钮。

**本次不做**：第二条全局顶栏、修改画布全屏几何、另造主题设置中心、重写 SSH 引擎、自动执行远程采集命令、Agent 代执行、多用户平台。

## 2. 现状诊断：问题不止是配色

以下结论按 2026-09-12 的源码核查，不把旧文档的目标当作现状。

| 问题 | 代码事实 | 体验影响 | 处理 |
|---|---|---|---|
| 主题割裂 | `styles.css:2–12` 固定蓝黑色；`app.js:165–170` xterm 独立硬编码颜色 | pure 亮色、狂狂帝下像嵌入另一个应用 | 完整主题桥接，含终端 ANSI 色 |
| 页面割裂 | `app.js:237–310` 连接库 / 编辑器 / 终端切屏；`styles.css:66` 列表限宽 720px | 大屏浪费、上下文丢失、返回成本高 | 主从布局，编辑抽屉 |
| 活跃终端无法恢复 | `app.js:77–79` 已连接按钮禁用；初始化总回连接库 | iframe 重建后连接还在，但进不去 | 已连接主动作改“打开终端”，只 attach |
| 关闭语义缺失 | 前端只有返回，后端已有 disconnect；重复 connect 会 teardown 旧连接 | 用户分不清隐藏、保活、断开与重连 | 显式动作和状态契约 |
| 输出与清理风险 | `app.js:187–198` 未设置 binaryType，却把二进制事件直接当 ArrayBuffer；新终端未集中销毁旧监听 | 可能无输出、旧连接串写、反复打开后泄漏 | 先修二进制接收和实例生命周期 |
| 状态与表单缺口 | 私钥口令后端支持但无输入；取消按钮无独立行为且缺 `type=button`；ready 帧语义不一致 | 提示与实际不符、取消可能保存 | 表单/状态机闭环 |
| 指纹闭环不足 | 使用原生 confirm；重置信任无 UI；保存指纹失败被吞；确认 60s 与握手 15s 不协调 | 无法核对与恢复，确认可能提前失效 | 专用信任对话框与错误分支 |
| 尺寸处理不足 | 仅 window resize；终端 100% 高叠加工具栏；attach 后未立即同步既有 PTY 尺寸 | 右栏挤压、字体/主题变化后裁切 | 观察实际容器并统一 fit/resize |

已有可复用基础：主机 CRUD、密码/私钥路径/SSH agent、ssh2 PTY、WS 输入输出、resize、host 侧存活连接、回放缓冲、TOFU 与变更拒绝、状态/断开/信任记录 REST。**不需要为了美化换框架或换传输栈。**

## 3. 信息架构

### 3.1 页面骨架

```text
DSH 现有会话头                         [ 对话 | 会话布 | SSH ]
───────────────────────────────────────────────────────────
主机导航（可收起）    │ [ web-01 × ] [ staging × ]          ⋯
搜索 / 新建          │ 主机身份、连接状态         查找 / 专注
────────────────────┼──────────────────────────────────────
收藏                 │
生产环境             │             终端
  web-01    已连接   │
  api-02    未连接   │
测试环境             │
  staging   已连接   │
────────────────────┼──────────────────────────────────────
已保存 N · 活跃 M    │ 已连接 · 信任状态           cols × rows
```

- 保留会话头第一行三段胶囊及画布内部的外部视图槽入口；**不重新排列官方会话头，不新增全局栏**。
- 上图中的终端工具区属于 SSH iframe 内部，不是在画布上再盖一条栏。
- 侧栏初值 232px，可在 208–288px 范围拖动；收起后由终端工具区的“主机”按钮召回。
- 第一版标签只对应**不同主机的既有运行连接**。同主机重复打开只聚焦 / attach，不新建 shell，更不能暗中断开重连。
- 未选主机：右侧显示最近连接与“新建主机”空态；不显示空白黑块、不铺服务器统计大卡片。
- 点击未连接主机先看摘要，显式“连接”才启动认证；点击已连接主机直接打开终端。

### 3.2 主机导航

主机条目两行：名称 / `username@host:port`；状态点配文字。当前选择用淡强调色底和细边线，而不是整块强品牌色。

- 首版：名称、地址、用户名联合搜索；分组；收藏；最近连接。
- 分组只组织导航，不等同于安全角色；“生产”标记需用户显式设置，不根据主机名猜测。
- 右键与“更多”菜单同源：打开终端、编辑、复制连接地址、查看信任记录、删除主机。
- 不在每一行同时常驻“连接 / 编辑 / 删除”三颗按钮。
- 已连接主机编辑地址 / 用户名时提示“仅影响下一次连接”，不能把正在运行的终端标题偷换成新目标。
- 删除活跃主机必须说明将断开多少活跃连接；删除不自动清除同 host:port 的信任记录。

### 3.3 连接编辑器

采用右侧 380–420px 抽屉；窄容器改为内部全宽面板，保留上下文与返回焦点。

- 基础：名称、主机、端口（22）、用户名（必填，不默认提权为 root）。
- 认证：密码 / 私钥 / SSH agent，按所选方式渐进显示相关项。
- 密码与私钥口令在发起连接时临时输入；保存主机不保存这些秘密。
- 私钥路径注明“位于运行 dsh web 的机器”，浏览器文件路径不能当作 host 路径。
- 高级折叠：分组、环境标签；超时 / 保活等仅在后端真实支持后开放。
- 操作：“保存”“保存并连接”“取消”；取消永不提交，失败保留非敏感输入。
- 错误靠近字段展示；连接错误显示原因与下一步，不再只用 alert。
- “检测连接”也属于真实认证行为，不在打开表单或输入地址时自动执行。

## 4. 三主题：同一结构，三种气质

### 4.1 主题身份与基线

| 主题 | 已有项目含义 | SSH 呈现 |
|---|---|---|
| pure / 原版 | 原生 DSH，不覆盖其令牌；包含原生亮 / 暗两态 | 中性表面、原生蓝、轻边界；终端跟随明暗 |
| zafkiel / 刻刻帝·永夜钟阁 | 桌面引擎锁定暗色；暗夜、绯红交互、鎏金装饰 | 墨夜层次、绯红选中、克制金色光标；终端无花纹 |
| kurkuriel / 狂狂帝·白夜逆钟 | 桌面引擎锁定亮色；骨白、血绯、枪铁 | 暖骨白表面、血绯焦点、枪铁辅助线；终端保持亮色可读 |

**以当前 CSS 为准，不照抄旧设计表。** 例如现役狂狂帝 `neutral-bluish-00=#f7f4f1`、`950=#0f0d0b`，遵循原生亮色语义；旧 `themes.md` 的部分色阶说明不等同于现役实现。

源码参考色：

| 样本 | pure | zafkiel | kurkuriel |
|---|---|---|---|
| 强调 | 原生令牌，兜底 `#3964fe` | `#c23a2e` | `#9e1b1b` |
| 基底 | 宿主最终表面 | `#0c0b11` | `#f7f4f1` |
| 层次样本 | 宿主 layer/overlay | `#171420` / `#1e1a27` | `#fcfaf8` / `#ffffff` |
| 代码表面样本 | 宿主代码色或实体表面 | `#121019` | `#ffffff` |

这些是设计对照值，不是要求在 SSH 中复制一份桌面 CSS。概念稿的独立色板只是模拟宿主，生产实现应消费实际主题。

### 4.2 主题接入方案

```text
现役桌面注入 / 官方 ctx.theme / 未来 appearance 皮肤
                         ↓
           宿主最终计算样式（body 优先）
                         ↓
     SSH client 桥接：白名单、实体色、版本号
                         ↓ 同源 postMessage
     iframe 的 --ssh-* 语义变量 + xterm theme
```

1. **宿主是唯一主题源。** SSH 不调用 setTheme/overrideTokens 去改变全局，也不增加独立皮肤选择器。
2. 从组件实际继承位置读取 computed CSS，优先 body，缺失再回根元素；`var(...)`、颜色函数和透明色不能原样假定为 xterm 可用颜色。
3. 首批映射：`--dsw-alias-bg-base`、`bg-layer-1/2`、`bg-overlay`、`border-l2`、`label-primary/secondary`、`interactive-bg-hover`、`--dsw-static-deepseek-450`，以及实际计算字体与字号。
4. 终端单独映射背景 / 前景 / 光标 / 选择区 / ANSI 16 色。语义红绿保留含义，不把所有颜色变成品牌红；正文目标对比度不低于 4.5:1。
5. 半透明宿主色在已知实体底色上合成后用于终端；终端**不透明**，不让壁纸、光晕和水印干扰输出。
6. 提议消息：`{ source: "dsh-ssh", type: "theme", version: 1, revision, scheme, skin, tokens, typography }`。发送 targetOrigin 固定；接收核验 origin、`event.source === parent` 与字段白名单。父页面也只接收自己的 iframe 消息。
7. iframe ready 握手后下发首个快照；主题/字体/明暗变化时去重更新；重新显示补发。官方订阅接口在实现前核验，不假设有不存在的方法。兜底监听 html/body 的主题属性及受控样式更新，禁止全页高频扫描。
8. 收到同一 revision 不重复 fit；变更后等待布局稳定，再 resize。主题切换不销毁 xterm，不断开 SSH。
9. 首帧优先同步同源宿主可用样式，失败使用原生明暗兜底；不得先闪固定黑底再切亮色。卸载回收观察器与事件。

**跨线边界：** 当前 appearance 只实现 M1 底座；其刻刻帝/狂狂帝皮肤下沉仍是 M2 计划。本提案不宣称普通浏览器已经具有三皮肤。SSH 现在跟随桌面最终样式和原生明暗，未来自动消费 appearance 的最终样式，无需依赖或导入另一线源码。

### 4.3 组件与密度

- 页面内边距 12–16px；4/8/12/16/24 间距档。
- 内容面板 12px 圆角，控件 8px，少量状态胶囊 999px；大弹层最多 16px。与 canvas 新提案同一圆润方向，但不把终端做成 16px 内嵌套卡片。
- 导航与工具区保持单层分隔；桌面控件 30–32px，触摸目标至少 40–44px。
- 正文跟随宿主，辅助信息约 12px；终端建议初值 13px，可调整到 12–20px，等宽字体优先 Cascadia Mono / Consolas。
- 标题装饰字体仅适合空态标题，不进入主机地址、工具按钮、终端和安全提示。
- 常态无大阴影；浮层轻阴影；暗色依靠表面与边框分层。
- 不做字符动效、持续光晕、移动水印或终端背景动画；状态变化保持直接，尊重 reduced-motion。

## 5. 生命周期：把“连接”说清楚

### 5.1 三种身份必须区分

- **主机配置 profileId**：保存的连接资料。
- **运行连接 runtimeId / generation**：一次实际 SSH + shell 的生命期。
- **查看器 viewerId**：一个 iframe / 标签对运行连接的附着。

现状 profile 与 runtime 共用 connId。首版可以保留旧路由和“一主机一运行连接”，但前端必须按实例/generation 绑定回调，避免旧 WS 写进新终端。同主机多 shell 需要独立 runtimeId 与新协议，不能只增加几个标签按钮。

### 5.2 操作契约

| 用户动作 | 预期行为 |
|---|---|
| 打开已连接主机 | attach 已有连接，不调用 connect、不重新问密码 |
| 切到对话/画布、收起导航 | 不结束 SSH；iframe 卸载时释放 viewer 与前端实例 |
| 关闭终端标签 | 首次说明“仅关闭查看，连接继续保留”；可选择“断开并关闭”；主机列表仍可恢复 |
| 断开连接 | 服务端 teardown，废止待确认 token，清理可控引用/缓冲；UI 保留本页末屏供查看 |
| 重新连接 | 显式创建新连接，提示旧 shell 已结束；凭据需要时重新输入，不重放任何命令 |
| 浏览器 WS 短断 | 可有限退避重附着；先核验服务器运行状态，不自动重新创建 SSH |
| SSH 自身关闭/认证失败 | 显示有原因的断开态；重连必须显式发起 |
| 关闭 DSH 服务 | 所有 SSH 结束；不宣称跨进程保活 |

“清理秘密”指不落盘、及时清输入框和可控引用；JavaScript/第三方库不承诺可证明的内存物理擦除。

### 5.3 状态模型

SSH 状态和浏览器传输状态分开：

- SSH：未连接 → 收集凭据 → 建立连接 → 待确认指纹（如需）→ 认证中 → shell 就绪 → 已连接 → 已断开 / 失败。
- WS：未附着 / 正在附着 / 已附着 / 失联重附着。
- 只有 shell 已就绪、viewer 具备写入权限时启用终端输入；不能在 ssh2 ready 事件发生时就提前报“终端已就绪”。
- 等待指纹可取消；确认等待与握手超时必须同一套时间预算；过期确认不能影响新 generation。
- 多窗口附着需明确输入/尺寸所有权：建议一个可写主 viewer，其余只读，显式接管；不能用“最后一个 resize 获胜”隐式争抢。

### 5.4 回放的真实边界

当前是约 256KiB 的原始字节回放，并非完整终端屏幕快照；单个超大 chunk 甚至可能越过名义上限。

- 首版修严格限额、字节序与新旧实例隔离，普通日志返回可回看。
- 原始环形缓冲截断可能切入 ANSI/UTF-8 序列，vim/top 等全屏 TUI 也不保证原样重建；**不能写“切回来总能原样恢复所有程序”**。
- 全屏精确恢复另设 spike：服务端终端状态快照/序列化、边界安全回放或明确的重绘交互；不得为重绘偷偷发送 Ctrl+L 等用户未操作的按键。
- 不追求完整历史审计，不自动把终端输出落盘。

## 6. 功能完备，但不堆满首屏

| 层级 | 能力 | 入口与边界 |
|---|---|---|
| 首版必需 | 主机 CRUD、搜索、分组、收藏、最近连接 | 主机导航；扩展字段先补归一化和迁移测试 |
| 首版必需 | 三认证、加密私钥口令、取消、字段校验 | 连接抽屉 / 临时凭据对话框 |
| 首版必需 | 指纹确认、变更拒绝、查看/忘记信任 | 身份行和详情；忘记不等于接受新指纹 |
| 首版必需 | 多主机标签、恢复、显式断开/重连 | 终端区；同主机限一运行连接 |
| 首版必需 | 选择复制、粘贴、查找、字号、清屏、专注 | 工具区少量图标 + 更多菜单；查找需核验 addon-search 并单独引入兼容依赖 |
| 首版必需 | 连接阶段、可行动错误、WS 与 SSH 区分 | 状态栏与内联提示；不伪造 RTT/CPU/内存 |
| 次版 | SFTP 浏览/上传/下载/重命名/传输队列 | 终端旁按需打开文件抽屉；覆盖/删除确认，远程路径与本机路径严格区分 |
| 次版 | 同主机多 shell、会话工作区布局记忆 | 独立 runtimeId；不是复制标签 UI |
| 后续选配 | SSH config 导入、ProxyJump、端口转发 | 独立安全评审；导入不得执行 ProxyCommand |
| 后续选配 | 选中文本送对话 / 命令片段 | 用户显式发送，可预览脱敏；不自动执行、不得借此修改模型链路 |

终端键盘约定：Ctrl+C 保持中断；Ctrl+Shift+C/V 用于复制/粘贴（浏览器权限不可用时提供替代）；不抢 Ctrl+L、Ctrl+R 等 shell 按键。多行或含控制字符粘贴先预览确认，保留 bracketed paste 语义，不自动追加回车。清屏必须区分“清除本地显示”与“向远端发送 clear”。

不默认做服务器仪表盘：CPU、内存、目录路径、延迟均须有可靠数据源；若未来增加，明确用户授权、采样周期和失败态，不能伪装成免费静态信息。

## 7. 响应式与无障碍

### 7.1 容器断点（初始提案，按实测微调）

| SSH 内容宽度 | 布局 |
|---|---|
| ≥ 960px | 232px 主机导航 + 终端；导航可调宽；工具文字可见 |
| 720–959px | 208px 紧凑导航；低频动作收菜单；标签横向滚动 |
| < 720px | 导航改模态抽屉，终端占满；一键召回主机 |
| < 480px | 只保留主机开关、当前身份和更多；其余折到菜单；编辑/信任面板全宽 |

- 依据 iframe / 面板的实际 `ResizeObserver` 尺寸或容器查询；官方右栏打开、左右拖拽、缩放、字体变更都覆盖。
- 根到终端必须 `height:100%` 的可靠链与 `min-width:0; min-height:0`；工具栏占固定/内容高度，终端取剩余高度，不再叠加两个 100%。
- fit 在容器可见且正尺寸时执行；同帧合并、cols/rows 去重、正整数限界；attach 后将初始尺寸送到真实 PTY。
- 控件和导航不横向溢出；终端自身按字符列数重排，不给 shell 输出硬加 CSS 自动折行。
- 窄屏“可用”不承诺所有 TUI 都能舒适操作；提示扩大终端或专注模式，不擅自缩小字体到不可读。
- 抽屉 focus trap、Esc 关闭、焦点归还触发器；终端聚焦时 Esc 应交给远程程序，只有浮层打开才拦截。
- 状态文字 + 图标，不仅靠颜色；键盘可达，focus-visible 清楚；触控命中足够；长 IPv6/指纹可复制和正确换行。
- **对比度逐主题校验**：辅助文字与警告 / 琥珀类语义色必须在其**实际底色**上 ≥ 4.5:1。实测狂狂帝的浅底最易失守（见 §13.1），实现时以真实宿主令牌复算，不能沿用桌面端配色表。
- 浮层关闭后焦点归还触发元素；触发器不可聚焦时回退到确定目标（如工具区按钮），**不得把 `document.body` 当作可恢复目标**——概念稿首轮实测即因此把焦点丢到 `body`（见 §13）。

### 7.2 专注模式

仅收起 SSH 内部导航和次要工具；不掩盖官方导航、桌面窗控或右侧栏，不重新做全屏壳。退出方式常驻且键盘可达。

## 8. 安全与错误恢复

- TOFU 是“首次信任”，不是证明主机身份。对话框列出 host:port、算法（后端实际返回才显示）、完整 SHA256 指纹和核验说明。
- 指纹不一致必须阻断；不能一个“继续”跳过。用户核验后，在信任管理中显式忘记旧记录，再次连接重新确认。
- 保存信任记录失败应报错并拒绝本次继续，不能吞错后返回成功。
- 所有密码/口令只在用户提交期间短暂使用；DOM 字段在成功、失败、取消和卸载时清空；不写 localStorage/日志/概念稿持久化。
- 主机配置存储仍以 host 为事实源；前端可存非敏感布局偏好，不存密钥、密码或终端输出。
- HTTP 与 WS 均做来源围栏；完善 Origin 的协议/主机/端口核对。围栏不是身份鉴权，不能宣称防住同机所有进程。
- 在增加多 viewer / 同主机多 shell 前引入短期附着凭证、运行实例归属与写入/尺寸权限。不得把运行连接 ID 本身当作授权证明。
- 指定信任范围仍为本机单用户；远程开放 DSH、多用户、跨设备分享终端不在本轮范围，必须另行认证与 TLS 设计。
- 限制 WS 帧尺寸、输出待发送队列、回放内存和 resize 范围；洪泛时对慢 viewer 断开/提示恢复，不无限堆积、不拖死所有连接。
- 未授权远程输出不渲染为 HTML；禁止任意 OSC 自动写剪贴板/打开链接；链接仅在用户手势下打开并校验协议。

## 9. 分期与实施落点

用 U0–U3 表示本次体验升级阶段，避免与原文 M1/M2 混淆；以下都还是计划。

| 阶段 | 交付 | 门槛 |
|---|---|---|
| **U0：可靠性闭环** | 二进制输出、实例清理、恢复 attach、取消/口令、状态机、指纹时序/清理/错误、尺寸同步、输入归属 | 先通过故障注入测试；真实可用再进入下一阶段 |
| **U1：统一工作区** | 双栏/抽屉、多主机标签、表单与空态、三主题桥接、响应式、复制粘贴/查找/字号 | 最小发布版本；三主题和原生明暗均过验收 |
| **U2：效率补齐** | SFTP、独立 runtime 多 shell、会话工作区记忆、精确终端恢复 spike | 每项单独验收；不把首版拖成大平台。**四项 SPIKE 已完成（2026-09-15，§14）：S2/S3/S4 全过 GO，S1 受阻待放行；多 shell 地基可行、布局记忆方案可进设计稿、精确恢复采纳方案 α（viewport serialize + 字节回放混合）** |
| **U3：高级连接** | 配置导入、跳板/转发、显式文本联动 | 另行安全与协议评审 |

建议实施文件边界：

- `client.js`：保留入口机制，只增加 SSH iframe 的主题/可见性/上下文桥接与回收。
- `app.js`：视图状态、主机导航、标签、编辑/信任/凭据浮层；逐步拆出本线自有模块，避免增长成不可维护单体。
- `styles.css`：局部 `--ssh-*` 令牌、容器布局与状态样式；不写跨线全局选择器。
- `lib/runtime.js`：状态机、generation、teardown、待确认项、回放/背压、输入/尺寸归属。
- `lib/store.js`：新增收藏/环境等字段的归一化和向后兼容；无凭据字段。
- `index.js`：必要协议与范围校验；若拆分前端模块，同步静态资源白名单路由。
- `test/`：主题消息白名单、状态机、恢复、销毁、并发 attach、回放边界、响应式/键盘浏览器测试。
- `README.md`、`design/CHANGELOG.md`：实施完成后逐项更新真实状态，不能把概念稿写成已上线。

继续保留原生 DOM + xterm；主题与工作区本身不需 React/Vue/Tailwind 等新框架。查找/SFTP 等若新增依赖须单独核验版本、体积与安装方式，不宣称整个后续方案零依赖。

## 10. 验收矩阵

### A. 视觉与布局

1. 桌面 pure-light、pure-dark、zafkiel-dark、kurkuriel-light 共四个实装组合；普通浏览器覆盖原生亮/暗，appearance 皮肤实际完成后再扩矩阵。
2. SSH 容器宽 360 / 480 / 720 / 960 / 1280，短高 400 与常用高 600/800；100% / 125% / 150% 缩放与字体上下限。
3. 打开官方右栏、拖动分隔、切会话、从画布进出：终端填满剩余空间、无双重纵向滚动条、无窗控碰撞。
4. 即时切主题，主机列表/输入框/弹层/xterm 同步，无蓝黑残留、无暗字暗底、无重建 SSH。
5. 200 字符主机名、IPv6、完整指纹、0/1/100 个主机；空态、搜索无结果、host API 不可达各有独立文案。

### B. 连接与安全

1. 三认证分别成功/失败/取消；加密私钥口令错误不泄露秘密；取消保存不改主机。
2. 首次指纹接受/拒绝/超时/记录写入失败/变更拒绝；断开后旧 token 不可复活连接。
3. 已连接主机打开仅 attach；重复点击不发第二个 connect；切换 30 次无旧输出串写或监听器累积。
4. iframe 刷新、短 WS 断网、SSH 主动退出、host 进程重启明确区分；不自动重放用户命令。
5. 多 viewer 输入/尺寸所有权确定；普通日志回放顺序正确；全屏 TUI 的恢复边界如实提示。
6. 非法 WS 形状、超大帧、负数/过大尺寸、持续输出洪泛均有界；慢 viewer 不拖垮其他连接。
7. 来源/消息伪造测试拒绝；秘密不出现在存储、日志、回显错误中；API 可达不等于已获得操作授权。

### C. 可用性

1. 从主机列表到已连接终端只需一次明确动作。
2. 首次连接有完整阶段反馈与取消入口；错误提供“检查地址 / 重新输入凭据 / 查看信任记录”等实际动作。
3. 全键盘完成新建、连接、信任确认、切标签、断开；弹层关闭后焦点归还。
4. 多行粘贴先确认，不追加回车；Ctrl+C 仍能打断程序；主题切换不改变 shell 输入。

本轮概念稿验证只证明设计演示的布局和本地交互，不替代以上真实 SSH 验收。

## 11. 待评审的三个取舍

1. **推荐采用主机侧栏 + 终端工作区。** 相比整页连接库，它保留上下文；代价是需要处理窄容器抽屉与标签状态。
2. **推荐终端默认完全跟随主题。** 狂狂帝是亮终端；若确有长期暗终端偏好，可后续增加终端专用对比度选项，但不另立全局皮肤。
3. **推荐 U0 + U1 为首个可发布范围。** SFTP 作为 U2 优先项；同主机多 shell、跳板/转发不能用 UI 占位冒充完成。

评审通过后再实施。切换到 Agent 模式只允许产出方案文件，并不自动等于批准业务改造。

## 14. U2.0 SPIKE 决策建议书（2026-09-15，四项技术验证完成）

> 完整报告见 [design/preview/2026-09-15-ssh-u2-spike-report.html](preview/2026-09-15-ssh-u2-spike-report.html)；脚本与原始数据归档 `_refs/scripts-archive/ssh-u2-spikes/`。goal 假设的「协议兼容/密钥认证/性能并发/安全审计」与本线规划不符，按 goal 契约以 §9「U2：效率补齐」真实清单执行。

### 14.1 四项结论一览

| SPIKE | 结论 | 置信依据 |
|---|---|---|
| S1 SFTP 能力与基准 | **受阻待放行**（脚本与判据已交付，护栏拦截未跑） | 判据已书面化；不阻塞 S2–S4 |
| S2 独立 runtimeId 多 shell | **GO** — RuntimeConn 多实例地基完全可行 | 真实 SshRuntime + 双实例 9/9：实例隔离、广播归属、尺寸归属、背压、U0 串线回归 |
| S3 会话工作区布局记忆 | **GO** — localStorage 白名单方案可直接进设计稿 | 11/11：回环钳制、敏感拦截（默认拒绝）、损坏容错、v1→v2 迁移、U1 共存、体积 3.2KB/100 profile |
| S4 精确终端恢复 | **GO（带条件）** — buffer 级 serialize/restore 是唯一能恢复 TUI 的路径，正常/TUI 双场景 100% 逐 cell 保真；数据量线性增长需配滚动上限 | 3/3 场景实测：A 正常 161KB/100%、B TUI 30KB/100%、C 270 行 622KB；对比 U0 字节回放（TUI 结构性无效） |

### 14.2 U2.0 总体判定：**GO（附三个实施前提）**

1. **协议改造**：attach 帧加 runtimeId；WS 路由按 runtimeId 分发；viewer 所有权表（可写主 + 只读 + 显式接管）在 runtime 层新增（S2 证实 `rc.sockets` Set 可扩展为 Map<viewer, permission>）。
2. **布局记忆落点**：localStorage key 与 U1 PREFS 分离（S3 证实命名空间隔离即可）；tabOrder 存 profileId 序列；写失败 try/catch 静默降级为无记忆。
3. **精确恢复采纳方案 α**：viewport 级 serialize（≈80KB/次）+ scrollback 走字节回放的混合方案；硬上限 + 截断标记；不偷偷按键（§5.4 红线）。

### 14.3 决策评审记录
