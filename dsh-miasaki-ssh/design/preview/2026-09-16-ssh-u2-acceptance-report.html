01架构：三层身份 + 附着票据

多 shell 的本质不是「多几个标签按钮」，而是把「主机资料、连接实例、shell 通道」三层身份拆开；安全前置是给运行实例发短期票据，让实例 id 不再是授权证明。

图 1 · 三层身份与授权路径 —— connId 保持对外稳定，runtimeId 与 shellId 在内部承担代次与通道语义

身份链

  • connId（profile，store.js 持久）— 对外名字，REST 不变
  • runtimeId（rt-<uuid>，一次 ssh2 Client 实例）— 重连即换代，旧代次票据/指纹确认联动失效
  • shellId（sh-<seq>，一条 shell channel）— 独立流 / 尺寸 / 回放环 / viewer 集合 / 写权

授权与写权

  • WS attach 必须持 POST /ssh/api/attach 签发的一次性 30s 票据；重放 / 过期 / teardown 作废 → TICKET_INVALID
  • 单写多读（决策 2）：非 owner 的 input / resize 一律拒收，接管走 shell.takeover，原 owner 即时收 write.revoked

v2 协议帧

  • 旧帧（无 v:2）→ 拒收 + VERSION_MISMATCH 提示刷新，不做双栈
  • attach { v, ticket, shellId|shellSeq, cols, rows }
  • input / resize { v, shellId, … } — 绑定校验集中在 currentShell(ws)，僵尸 viewer 与错 shellId 全部在此被拒
  • shell.open / shell.close / shell.takeover / snapshot；shell 结束 ≠ 连接结束，标签保留为「会话已结束」

03U2.3 工作区记忆与 U2.4 精确恢复

两项都在 U2.1 的地基上以最小面积落地：记忆是「两张据 + 恢复形状不自动连接」；恢复是「官方 serialize addon + 三路判定 + 可单独退出的降级」。

U2.3 · 决策 4 拆两张据

  • 偏好（字号 / rail 折叠 / 专注）→ localStorage['dsh-ssh:prefs'] v2，跨标签页共享
  • 快照（标签集合 + 激活项 + 抽屉态）→ sessionStorage['dsh-ssh:workspace'] v1，按标签页隔离
  • sessionStore 统一封装，全 try/catch：损坏 / 版本不认 / 无痕模式一律回默认，绝不白屏
  • 恢复语义 = 恢复标签形状，绝不自动连接 / 输凭据；失效 connId 静默丢弃 + 提示
  • 顺带修复：上一会话脱敏写入使 PREFS_KEY 与 LAST_TAB_KEY 同为 '***'、两据同键互相覆盖

U2.4 · 官方 addon（方案 A）

  • @xterm/addon-serialize 0.14.0 精确锁定（探针 B 已证与 xterm 6.0.0 兼容）
  • 输出空闲 1.5s 采集序列化快照上报 host；每 shell 内存态封顶 128KiB、scrollback 500 行，不落盘
  • 恢复三路判定：快照帧优先（reset 后重放）/ 回放兜底（刷新后）/ 重附着丢弃整段回放（防翻倍）
  • addon 缺失或加载失败 → 静默降级为回放恢复；删包即可单独退出 U2.4，不动 U2.1/U2.3
