## 1. 结论摘要

**三条结论。**

1. **两个参考仓库都不是会话画布内核，不可移植。** `cleancode` 是 Electron + React Flow 的本地开发工作台，其连线语义是"终端启动依赖"；`dsh-comfyui` 是 ComfyUI 的服务/工具集成插件，其图语义是"计算节点依赖"。二者的图模型与本线的**会话 fork/merge 谱系**不同构——搬用会引入第二套事实源，直接违反本线红线。**可借鉴的是表现层与状态呈现，不是架构。**

2. **界面瓶颈不在"缺功能"，而在视觉语言不统一。** 现状是上游 dsh-synapse 的默认观感：卡片圆角 7px、连线 1.5px 灰、阴影只有"有/无"两态、字号 10/11/12px 三档偏小、4 个操作按钮以 24px 圆形浮在卡片右缘外。这些是"能用"而非"高级"的来源，与功能完备度无关。

3. **建议四步走，全部落在表现层，每步独立可验收。** V1 令牌化与圆润化 → V2 连线语义与端点 → V3 状态徽标与信息层次 → V4 收口与动效统一。任一步中止都不产生半成品，且都不触碰会话数据。

- 核查版本：默认分支 `master`，commit `b0a4e31`（2026-09-03），包版本 `0.4.0`。
- 许可证：MIT，`Copyright (c) 2026 dsh-comfyui contributors`。
- 真实定位：DSH 驱动 ComfyUI 的**服务/工具集成插件**（TypeScript + Node ESM + React 18 面板），提供工作流库、参数、资产与任务队列管理。**不提供会话节点、端口连线编辑或 fork/merge 画布内核。**
- 可借鉴（与本线"合并草稿/执行流"状态机同构）：
  - **五态任务模型**：`pending / in_progress / completed / failed / cancelled`，活跃队列与历史分区；

### 2.3 共同判断

两者共同证明：**"高级感"来自一致性，而非特效**——统一的圆角档位、语义化的表面/边框 token、分层阴影、克制的连接点、150ms 级的统一反馈节奏。这些**全部可以在原生 CSS 内实现**，无需任何新依赖。

## 4. 问题诊断

### 4.1 视觉层：五个"不像成品"的具体来源

1. **圆角档位与尺寸脱节。** 卡片 7px，内部徽标 9px（近全圆），按钮 6px，拖动手柄 4px——同一张卡上并存 4/6/7/9px 四档，视觉上"碎"。参考 cleancode 的做法是外层 20px、按钮 8px 的**两档结构**。
2. **阴影只有"有/无"两态。** 常态与 hover 之间缺"拖动态"；拖拽时卡片贴地，与"拖动"这一最强交互不符。
3. **边框与线身份无关。** 所有卡片同色边框，而每条会话线已有自己的 `--thread-color`（侧栏树点已在用，`app.js tree-row` 内联 `--thread-color`）。画布上这份身份信息被浪费。
4. **字阶偏小、行距偏紧。** meta 10px 已低于可读下限；`zoomCanvas` 步进 0.05，常见停留 0.8~0.9，此时 10px 实际渲染约 8px。正文 12px/1.58 在 310px 宽卡上显得拥挤。
5. **操作按钮浮在卡外。** `right:-12px` 的 4 个圆钮在密集布局下与相邻卡片的连线、甚至邻卡本体视觉粘连。

### 4.2 交互层

1. **连线无落点。** 会话布虽非端口图，但"线从卡边凭空长出"缺少物理锚定感——这是"节点感"最弱的一环。
2. **活动路径只靠颜色区分。** `active-connector` 仅改色不改粗细，在 0.8 缩放 + 浅色主题下辨识度低。
3. **无内容分级。** 缩到 0.5 以下时卡片内容仍全量渲染（仅视口外不挂载），文字糊成一团，而小地图反而更清晰——"缩远了更难看"的根因。
4. **反馈节奏不统一。** 检查器 180ms、动作按钮 140/150ms、侧栏无过渡——缺统一的时长令牌。

## 5. 设计原则

1. **一致性优先于装饰。** 建立令牌，所有取值来自令牌；不再新增裸值。
2. **零新依赖、零 schema 变更。** 仅 CSS + 既有 DOM 结构（端点圆点需在 `conversationCard` 内加 1~2 个 `<span>`）。
3. **不牺牲信息密度。** 卡片尺寸常量不变（与连线几何、碰撞检测、框选命中、小地图、布局五处强耦合），只调整内部间距与字阶。
4. **三主题 × 明暗双态等价。** 任何新颜色必须走 `--canvas-accent` 派生链或既有语义色；**暗色下靠"表面分层 + 边框提亮"，不靠阴影**。
5. **关掉即原生。** 不做全局动效；动效仅服务状态变化，且尊重 `prefers-reduced-motion`。

## 6. 视觉规范（提案）

### 6.1 圆角

| 元素 | 现值 | 提案 | 理由 |
|---|---|---|---|
| 会话卡 | 7px | **16px** | 310px 宽下圆角率 5.2%，圆润且保持结构感；20px 会让 276px 高卡的视觉重心发散 |
| 卡片内按钮 | 6px | **8px** | 与外层 16px 构成两档结构 |
| 徽标 / 药丸 | 9px | **999px** | 已是胶囊，统一语义 |
| 拖动手柄 | 4px | **6px** | 与外层同系 |
| 小地图 | 8px | **12px** | 浮层与卡片同系 |
| 多选条 / 手势气泡 | 10px | **14px** | 同上 |

内层圆角经验式：`内层半径 ≈ 外层半径 − 内层到外缘间距`（16 − 12 = 4px 为下限，实际取 8px，因内层元素多为小尺寸按钮）。

### 6.2 阴影（三级 + 合并态）

| 状态 | 值（亮色） |
|---|---|
| 静置 | `0 1px 2px rgba(15,23,42,.04), 0 6px 16px rgba(15,23,42,.06)` |
| 悬停 | `0 2px 4px rgba(15,23,42,.05), 0 12px 28px rgba(15,23,42,.10)` |
| 拖动 / 选中 | `0 4px 8px rgba(15,23,42,.06), 0 20px 44px rgba(15,23,42,.16)` |
| 合并节点 | 在静置/悬停基础上叠加 `0 0 0 1px rgba(124,58,237,.18)` 环 |

**暗色态**：阴影改 `rgba(0,0,0,.5 / .62 / .72)` 三档，并提升卡片表面亮度（`#1b2028`）与边框亮度——暗色分层靠表面，不靠阴影。

### 6.3 边框与线身份

- 静置：`1px solid color-mix(in srgb, var(--thread-color) 14%, var(--canvas-border))`
- 悬停：混比提到 28%
- 选中：`--canvas-accent` 外环（保留现有 `selected` 语义）
- 合并节点：紫色边 `#a78bfa` 保留，圆角与外层一致

新增令牌 `--canvas-border`（亮 `#d8e0e8` / 暗 `#2c3138`），替换文件内裸值。

### 6.4 字阶与间距

| 元素 | 现值 | 提案 |
|---|---|---|
| 卡片标题 | 13px / 720 | **14px / 600**（见下方待确认项） |
| meta | 10px | **11px** |
| 正文（卡内 answer） | 12px / 1.58 | **12.5px / 1.65** |
| 徽标 | 10px | **11px** |
| 卡片头内边距 | `15px 12px 8px` | `16px 14px 10px` |
| 正文外边距 | `10px 14px` | `12px 14px` |

> **待实机确认项（字重）。** 现有 `720 / 650 / 750` 属可变字重写法。若 DSH 主题字体（`--font-sans` 链）在 Windows 上回退到非可变字体，浏览器取最近档 700，此时 `720` 与 `700` 等价，改 `600` 会**变细**。**建议先对三主题各截一张对比图再定；若偏细，回落 650。** 本项不阻塞 V1 其余改动。

### 6.5 连线

| 维度 | 现值 | 提案 |
|---|---|---|
| 粗细（普通） | 1.5px | **2px** |
| 粗细（活动路径） | 1.5px | **2.5px** |
| 线帽 | 默认 | `stroke-linecap: round` |
| 颜色（亮） | `#aebbc9` | `#c3cdd9`（降对比，退到卡片之后） |
| 颜色（暗） | 同上 | `#3a4048` |
| 合并边 | 1.5px `#8b5cf6` | 2px；草稿虚线 `6 4`；紫色语义保留 |
| 端点 | 无 | 卡右缘中点"出点" + 卡左缘中点"入点"，6px 圆，`opacity:.35`；卡 hover/选中时 `.8` |

**端点是本次"节点感"提升的关键项**：它把"线"从装饰变成"连接"，成本极低（1 个绝对定位 span + 2 条 CSS 规则）。端点须 `pointer-events: none`，拖拽仍走既有 `node-handle`。

### 6.6 操作按钮处置（三方案对比）

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| 甲 | 保持卡外浮钮，仅统一圆角与阴影 | 改动最小、效率不变 | 未解决密集布局下的视觉粘连 |
| **乙（推荐）** | 卡外只留 1 个主操作（追问），其余收进 footer hover 行 | 兼顾效率与整洁，卡缘只剩一个视觉焦点 | footer 交互需微调，hover 在触屏不可用 |
| 丙 | 全部收进 footer | 最干净 | 追问效率下降（核心动作多一步） |

推荐**乙**：追问是最高频动作，保留其卡外可点性；分支 / 合并 / 折叠属低频，收进 footer 更合理。触屏场景由 footer 常显兜底。

### 6.7 内容分级（LOD）

按 `state.zoom` 三档，由 `applyCanvasTransform`（既有单一出口）写入 `.canvas-content[data-lod]`，CSS 负责表现：

| 档位 | 条件 | 表现 |
|---|---|---|
| `full` | `zoom ≥ 0.8` | 现状全内容 |
| `compact` | `0.5 ≤ zoom < 0.8` | 隐藏 footer 按钮行；正文 `-webkit-line-clamp: 6` |
| `mini` | `zoom < 0.5` | 只渲染 head（色点 + 标题 + 徽标）；卡高收为 56px；隐藏正文与 footer |

**注意**：LOD **不改变** `CARD_HEIGHT` 常量——命中检测、连线几何、布局仍按 276px 计算，避免牵动五处几何计算。LOD 只改 CSS 表现，不改 `visibleCardIds` 判据。

## 7. 分阶段计划

### V1 — 令牌化与圆润化（纯 CSS，零 DOM 变更）

- 新增令牌：`--canvas-border`、`--node-radius`、`--node-shadow-rest/-hover/-drag`、`--edge-width/-color`、`--motion-fast`(150ms) / `--motion-base`(180ms)
- 应用 §6.1 / 6.2 / 6.3 / 6.4
- 替换文件内裸值为令牌（约 30~40 处）
- 验收：89 测试全绿；三主题 × 明暗共 6 张截图圆角/阴影/边框一致；无新增依赖

### V2 — 连线语义与端点

- `app.js`：`connectorPath` 算法**保持不变**；`conversationCard` 增加出/入点 span 各 1 个
- CSS：§6.5 全部
- 验收：活动路径在 0.5 / 0.8 / 1.0 三档缩放下可辨识；合并双入边与 fork 单边视觉可区分；端点随卡 hover 增强

### V3 — 状态徽标与信息层次

- 统一徽标体系：把现有 `工具 N`、`失败`、`回复中`、`◆ 合并`、`已被吸收` 收敛为一套（高 18px、字 11px、胶囊、语义色）
- **线尾卡状态带**：借鉴 comfyui 五态，把合并草稿的 `draft / pending / committed / failed` 与 `mergeStale` 表达为卡头右侧"状态点 + 文案"（现为 `.merge-plan-stale` 说明条 + 禁用按钮，信息位置偏低、需滚动才见）
- 验收：任一卡片状态下，一眼可判"这条线处于什么阶段"

### V4 — 收口

- 小地图、多选条、手势气泡、检查器、空状态统一到令牌
- 动效统一：仅 `transform` / `opacity`，150ms `cubic-bezier(.23,1,.32,1)`，`prefers-reduced-motion: reduce` 全关
- 滚动条、focus ring 一致性复查
- 验收：视觉走查清单逐项通过；无 10px 以下字号

### V5（可选，需单独决议）— 任务/产物呈现适配

仅在用户明确要接外部执行类插件（ComfyUI 类）时启动。形态是**只读适配器**：把 DSH 会话里的工具调用投影为任务状态徽标与产物引用；画布不建执行引擎、不存第二套账本。**不在本次范围内。**

## 8. 红线与不可动契约

1. **DSH session log 唯一事实源**；不新增/修改会话 schema 字段（V1–V4 全部纯表现层）。
2. **不引入第三方依赖**（React Flow、动画库等一律不引）。
3. **`CARD_WIDTH = 310` / `CARD_HEIGHT = 276` / `CARD_GAP_Y = 42` 保持不变**——被连线几何、碰撞检测、框选命中、小地图、布局五处引用。
4. **`--canvas-accent` 派生链**（`-hover` / `-ink` / `-soft`）与三主题（pure / zafkiel / kurkuriel）兼容性不得破坏。
5. **语义色不得挪用**：live 绿、merge 紫、错误红、警示橙各自语义不变（参考 cleancode 的"成功/失败边色"不可直接套到本线 fork/merge 语义上）。
6. **既有测试锚点不得为视觉改动而放宽**：
   - `canvas-runtime.test.js` 的 connectors 颜色断言——若因令牌化失效，**应改断令牌形式，不得删除断言**；
   - `header-adaptive.test.js` 的胶囊高度契约（控件总高 ≤ 30px）；
   - `external-views.test.js` 的跨线红线（`app.js` / `client.js` 不得出现具体视图名）。

## 9. 风险
