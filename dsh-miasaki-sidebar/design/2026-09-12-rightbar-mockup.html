diff 阅读器的三个关键取舍

项决定理由
换行面板宽 < 560px 时默认开，可关400px 面板等宽字体约 40 字符宽，长行横向滚动是窄栏第一可读性瓶颈
上下文扩展以 context=N 重取（git diff -U<N>）不在本地补行，避免与所选基线漂移
大文件单文件 > 2000 行只渲染可视 hunk 窗口现上限 20000 行全部进 DOM，展开即卡

形态为什么从「底部面板」改判为「右栏内嵌」

维度旧设计（底部面板）右栏内嵌
入口前提标题栏按钮注入 —— 已随壳退役作废官方 tab 类型，已有
分栏 / 浮窗需自研推挤 + 高度变量 + spike官方 split() / float() 白拿
与审查并排需自研布局官方分栏，天然成立
对对话区全宽横贯，压扁正文只在右栏内，不侵占

宿主已自带的 PTY 栈（0.1.5-rc.1 实测）

包提供
dsh-subprocessctx.subprocess.spawnTerminal(spec) → 句柄（pid / output / write / 信号 / terminate）不需要 Agent
dsh-subprocess-local本地实现，依赖 node-pty@1.2.0-beta.15
dsh-terminalctx.terminals：owner 作用域 PTY 注册表（要求 Agent 句柄，本插件不可用）
关键发现：node-pty 已随宿主安装，且带 prebuilds/win32-x64/（conpty.node、OpenConsole.exe、conpty.dll）。其安装脚本是 node scripts/prebuild.js || node-gyp rebuild，预编译命中即跳过编译 —— 旧设计里「Windows 需 VS Build Tools 编译」这道硬门不成立。
唯一真缺口：官方 SubprocessTerminalHandle 没有 resize（rows/cols 只在 spawn 时读取）；而 node-pty 的 IPty 有 resize(cols, rows)。这就是「用官方 seam」与「自持 pty」两条路线的取舍点。

三、落地顺序

P0
数据一致性
详情基线随视图、重命名支持、effect 依赖、错误可见化。属缺陷修复，优先级最高。
P1
diff 阅读器
行号 / hunk 头 / 换行默认开 / 上下文扩展 / 变更跳转 / 虚拟化 / 主点击展开 / 点名移位。
P2
内嵌终端
先 spike 官方 seam（无 resize），不可接受再转自持 node-pty + WS + xterm。
P3
联动深化
从 diff 行跳官方预览定位、分栏并排、整仓单次 diff。
