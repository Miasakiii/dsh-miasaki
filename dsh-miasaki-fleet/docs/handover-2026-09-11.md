## 5. 环境陷阱（本轮实测踩坑，**最省时间的一节**）

### 5.1 ⚠️ harness 的 `pwsh` 是 PS 5.1，派单器需要 PS7

本机 DSH harness 默认 shell 为 **PowerShell 5.1.26100**，而 `dispatch-task.ps1` 使用 PS7 语法（`??` 运算符）。

- 用 `[Parser]::ParseFile` 在 5.1 下校验会得到 **14 个假语法错误**（脚本其实健康）
- 必须显式调用绝对路径：`%LOCALAPPDATA%\Microsoft\WindowsApps\pwsh.exe`（实测 **7.6.5**）
- `dispatch-task.ps1` 头部注释已记录此事（「where pwsh 找不到」）

### 5.2 ⚠️ .NET 的 `\s` 含换行符，`^\s*` 会吃穿换行

`Resolve-RequiredCaps` 的正则**必须**用 `[^\S\r\n]*`（行内空白）而非 `\s*`：
`(?m)` 下 `\s` 可跨越换行，`^\s*` 会锚定到**下一行**行首，导致**永远匹配不到目标行**
（已实测：表现为闸门静默走「跳过」分支）。现已在代码注释与 README 中标注。

### 5.3 ⚠️ PowerShell 的 `-replace` / `-Encoding` 会损坏中文往返

本轮三次踩坑：

- `Get-Content -Raw` + `.Replace()` + `Set-Content -Encoding UTF8` 写回后，
  中文行的首字符被吃（`agents/coder` → `gents/coder`）——`$Matches` 残留与引号解析所致
- 更隐蔽的是：**read 工具显示正常，但 PS 脚本读到的不同**（中文行的字节与显示不一致）
- **对策**：任务书里需要机器解析的字段一律用 **ASCII 形式**（`requires:`）。
  中文 `需要能力：` 语法仍支持，但**不要依赖**
- **写工作区外文件优先用 write/edit 工具**，不要用 PowerShell 文本操作

### 5.4 其他

- **`graph-events.jsonl` 是 tracked 文件**，但它此前从未存在（总线版本 0）——
  接手后若发现它缺失，说明提交没带上，需重建或接受版本回落

### 9.2 ⚠️ 首个 G0 指纹契约边界：共享滚动产物不该进 `artifacts[]`

**现象**：为 t-0004 更新 `agents/claude/notes.md` 后，独立指纹复验报
`FAIL t-0003 agents/claude/notes.md` —— t-0003 的 `result.json` 所记 sha256 失效。

**根因（不是 bug，是契约边界）**：`notes.md` 是**被多个任务共享、且被设计为持续滚动**的追加文件
（每份 brief 都写「notes.md 追加要点」），而 `result.json` 的 `artifacts[]` 语义是
**不可变产物指纹**（供 consumes 校验与「产物是否被事后篡改」判定，见 `schemas/result.schema.json`）。
两者语义天然冲突：**每追加一次，所有引用它的历史任务指纹都会失效** ——
指纹机制会被「预期内的滚动」噪声淹没，真篡改反而淹没在噪声里。

**本轮处置**：把 `notes.md` 从两个任务的 `artifacts[]` **移到 `evidence[]`**
（`evidence[].note` 可自由记载变更沿革），`artifacts[]` 只保留任务专属、内容稳定的产物。
改后：指纹复验全 OK、两份契约均 `validateResult` 通过、`validate-bus` 26 文件 0 错误。

**待 Operator 裁决的建议**（本会话未擅自扩到协议层）：

1. **短期（零成本）**：维持本轮做法 —— 共享滚动文件列 `evidence`，并在 §4.6 brief 模板写明
   「notes.md 不计入 artifacts 指纹」；
2. **中期**：notes 改为**按任务分片**（如 `agents/<id>/notes/<task-id>.md`），
   每个分片即不可变产物，可正常进 `artifacts[]`；
3. 若维持单文件，则需在契约里**显式豁免** notes.md 的指纹校验，并接受其永久失效。

> 本项与 §8.3 第 3 条（notes.md 口径矛盾）**同源**：都源于 notes.md 的定位未定死。
