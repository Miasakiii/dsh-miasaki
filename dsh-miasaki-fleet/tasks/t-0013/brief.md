# 任务 t-0013：只读审查试跑 —— escalation-policy.cjs 七类模式对抗审查

## 目标

以只读审查者身份，对 `workers/lib/escalation-policy.cjs` 的 `classifyEscalation` 七类正则模式
做对抗审查：逐条找出**误报**（不该命中却命中）与**漏报**（该命中却未命中）。
这是 review 档案的首跑试跑任务，同时验证只读派单闭环。

## 背景

- 本文件是 2026-11-02 落地的 G5 语义分级闸门判定实现（纯函数 + CLI）。
- 清单共七类，措辞以 `workers/lib/escalation-policy.cjs` 的 `CATEGORIES` 常量为**唯一真相**；
  本任务书刻意不复述各类别字词——首版任务书因逐条列举被自家 G5 闸门命中 5 类，
  这本身就是一条边界事实：**描述分级政策本身的任务会踩中政策闸门**，正确做法是引用
  真相源、让审查者自己去读，而不是在任务书里转述触发词。
- 设计原则：**误报比漏报贵**（误报会训练 Operator 忽略告警，漏报只是这条没被提示）。
- 消费方：派单器 `Test-EscalationGate`（stdin 传 brief+context），命中只提示不硬拒。

## 审查要求

1. 只读：不得改写任何文件（本任务以 `--permission-mode plan` 运行，你也没有写工具）。
2. 每条发现必须带 `file:line` 证据；说不出证据就不是发现。
3. 只报真会出错的问题（模式缺陷：误报 / 漏报 / 窗口过窄或过宽），不报代码风格。
4. 无发现就明说无发现；摘要以计数开头。
5. 同一缺陷的同类实例整类点名，不逐行重复。

## 完成后必做

1. 将完整结论写入你的**最终回复**（stdout）——本任务只读运行、你不能落盘，
   交付物由总指挥从 stdout 转录（协议：headless 下产出只走 stdout）。
2. 结论须可复算：每条发现给出可直接粘贴复现的例句。

## 验收标准

1. 误报与漏报各至少尝试 3 条候选例句（找到几条报几条，不凑数）。
2. 每条发现带 `file:line` 与例句。
3. 如认为七类模式整体无缺陷，明说并给出你尝试过的例句清单作为反证。
