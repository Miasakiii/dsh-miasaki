## 1. 需求边界

- 用户要的是**预设**（内置可选），不是"再做一个上传入口"；上传链路是 M2.5 的，保留不动；
- 参考图的形态给了明确要求：**圆角方形图标 + 网格排列 + 下方名称 + 选中态**；
- 第二款必须是用户自己给的那张图（「头像」），排第二位。

---

## 2. 为什么是程序化生成

| 方案 | 代价 |
|---|---|
| 放一批 PNG 资源 | 需要先有图：要么外部素材（本仓其余线没有可用的同风格图标集），要么手工设计八张 |
| 复用 desktop 线的 `ui/icons/*` 素材 | **跨线取素材** = 把两条线绑在一起，正是本仓明令避免的耦合（各线零耦合、只共享 shared-docs） |
| 引 `sharp` / `canvas` 生成 | 破坏本线**零第三方依赖**硬纪律；且 link 装载下解析失败会拖垮整个 profile |
| **自己画：纯 JS 光栅器 + `node:zlib` 编 PNG** | 多写约 300 行；换来零依赖、零资源、参数化（配色/圆角/构图全是数据） |

选最后一条。交付物仍是**普通 PNG 文件**，因此 §6 的"壳侧零改动"成立。

## 3. 渲染管线（`lib/icon-presets.js`）

```
归一化画布坐标 (0..1)
   ↓ 每个图元算 SDF 距离
圆角矩形 / 圆 → coverage = clamp(0.5 - d/pixel)      ← 解析式抗锯齿，不做超采样
   ↓ 逐层 alpha-over（底 → deco → 徽记 → 高光）
   ↓ × 圆角方遮罩（23.5%，与 make-icons.mjs 同一倒角口径）
RGBA 像素 → PNG（IHDR + IDAT(zlib deflate) + IEND，CRC32 表驱动）
```

要点：

- **不做超采样**：SDF 覆盖率本身就是抗锯齿（边缘 ±半像素线性过渡），512×512 单张毫秒级；
- **PNG 编码手写**：`crc32`（表驱动）+ chunk 组装 + `node:zlib` 的 `deflateSync`；
  每行前置一个 filter 字节（0 = None），缺了任何解码器都会报错 —— 单测直接解析 chunk 自查 CRC 与 zlib 流；
- **可复现**：同 id 两次渲染逐字节一致（单测钉死）→ 落盘可以"内容相同就跳过"，不会每次请求都重写磁盘。

## 4. 骨架与配色怎么定的

骨架（抽象「M」）先做了四版候选 —— A 两竖块+两斜点（下点与右块粘连）、B 两竖块+中央竖排两点、
C 左右各一组「短块+长块」+ 中央两点、D 三竖条+一点 —— **全部渲染出来拼图目检**后选 **C**
（方块 + 圆点的像素感，与参考图的视觉语言最接近）。这一步只花了几分钟，却避免了"凭想象定稿"。

配色八款共用骨架（换色不换形）；「暗夜玻璃」初版对比度太低（图案几乎看不见）与「蒙德里安」
初版（四象限拼贴把图案吃掉）都是**目检发现后改的**：

- 暗夜玻璃 → 底色提亮一档 + 徽记提到 `#5b647a`；
- 蒙德里安 → 改为「白底 + 三角色块（deco 层）+ 黑徽记」，为此给渲染器加了 `deco` 装饰层
  （画在底与徽记之间），比初版的"四象限 + 网格线"干净得多。

## 5. 「头像」位图预设（用户点名的那张图）

原图（530×428 JPEG）有一个坑：**边缘一圈是纯黑描边**（把黑边当白色做"自动裁边"会判断错，
实测四角像素是 `0,0,0`）。所以处理链必须**先 trim**：

```
trim(threshold 12)              → 482×420（去掉四周黑边）
居中裁方                        → 420×420
resize 512 (cover)
圆角蒙版 rx = 512 × 0.235 = 120
png({ palette: true, quality: 92, dither: 0.4 })   → 471 KB → 97 KB（肉眼无差）
```

产物入库 `assets/presets/portrait.png`，来源与参数记在同目录 README。
生成脚本**不入库**（它依赖 `sharp`，而 `sharp` 只在 desktop 线的构建链里 —— 本线零依赖）。

`lib/icon-presets.js` 里位图预设只写 `asset: 'assets/presets/portrait.png'`；
host 侧统一走「取字节 → 落盘」，**位图与程序化在 host 眼里没有区别**。

## 6. 为什么跨线契约一个字不用改

桌面壳（M2.5 已上线）只认三件事：`config.json` 的 `avatar.source`、
`avatars/` 目录、文件名白名单 `^[\w][\w.-]{0,80}\.png$`。

预设图标落盘成 `avatars/preset-<id>.png` —— 三条全部满足，`source` 就是
`/appearance/avatar/preset-<id>.png`。**壳侧完全不知道"预设"这回事**，
不需要新路由、不需要新字段、不需要重建 EXE 之外的任何改动（连重建都不需要：M2.5 的壳已经会读）。

这也是把"落盘"放在 host 而不是"面板直接把预设图上传一遍"的原因：一次生成、处处可用，
且用户能像对待自己上传的图一样对待预设（手改目录、删除、复制）。

## 7. 面板形态

```
应用图标
┌──────┬──────┬──────┐
│ 默认 │ 头像 │暗夜玻璃│  ← 选中格：官方 bg-module-platform + neutral-bluish-400 描边
├──────┼──────┼──────┤     （与官方「通用设置」页的选中态同源，M2.6 风格延续）
│素雅银│果冻蓝│缠线绿│
├──────┼──────┼──────┤
│蒙德里安│暖橙│ 流光 │
└──────┴──────┴──────┘
自定义                            [上传图片…] [清除]
（我的上传：pills —— 目录里除 preset-* 之外的文件）
```

- 网格 `repeat(auto-fill, minmax(104px, 1fr))`：窄容器自动降列，不写死列数；
- 「我的上传」**过滤掉 `preset-*`** —— 预设是系统生成的，不该混进用户资产；
- 未设置时（`source === ''`）九宫格无选中格，用户仍可点任意一款立即生效。

## 8. 失败面

| 面 | 处理 |
|---|---|
| 无 `dataDir` | `/presets` 返回空清单 + `persistent: false`，面板给提示（**不谎报可用**） |
| 位图资源缺失 | `presetBytes` 返回 null → 该款跳过落盘（其余照常），不抛错 |
| 渲染异常 | 落盘包在 try/catch 里，失败只记日志；面板已有清单仍可点选已落盘的款 |
| 磁盘写入失败 | 同上；已有旧文件时用户仍能用旧图标 |
| 未知 id | `renderPresetPng` / `presetAssetPath` 返回 null（单测覆盖） |
