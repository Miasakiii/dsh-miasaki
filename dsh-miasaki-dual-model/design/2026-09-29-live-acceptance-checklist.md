## 前置（缺一不可）

- [ ] **1. 重启 `dsh web`** —— host 半改了 `index.js`；且本体补丁只在启动时加载
- [ ] **2. 浏览器强刷**（`Ctrl+Shift+R`）
- [ ] **3. 补丁在位**：`node dsh-miasaki-dual-model/patches/dsh-api-session-controller/patch.mjs status`
      → 期望 `状态 patched`。**这是本次修复能生效的前提** —— 2026-09-29 查明它此前是 `original`，
      即核心能力当时根本没启用
- [ ] **4. 准备两个模型**（关键）：
      - 一个**支持图片**的 → 作辅助模型
      - 一个**不支持图片**的 → 作主模型（第 5 项专验这个组合）

> 第 5 项是本线的**硬契约**：主模型看不了图时，图必须由辅助模型接走，
> **不能静默丢掉**。它也是本次代码修复直接针对的那条链 —— 修复前，一旦
> pre-step 判定失败就可能出现「发得出去、模型没收到」。

## A. 可自动化的部分（HTTP / DOM 层，不必人工看）

| # | 项 | 判据 | 怎么验 |
|---|---|---|---|
| A1 | 同源围栏 | 非环回 `Host` 或 `Origin` 与 `Host` 不一致 → **403** | `curl -H "Host: evil.test" http://127.0.0.1:<port>/dual-model/api/state` |
| A2 | 能力目录 | 响应里 `visionModels` **只含支持图片的模型**；`providers` 非空 | 同上接口，看返回体 |
| A3 | 图片归属结论 | `imageOwner` ∈ `primary` / `assist` / `none`，且与 `primaryVision`/`assistVision` 自洽 | 同上接口，换不同主模型各看一次 |
| A4 | 控件注册 | 输入框右下角（`conversation.input.right`）存在触发钮 | DevTools 查 DOM 或浏览器自动化 |

## B. 需要人眼的部分（真机 + 真模型）

### B1 · 控件出现与配置

- [ ] 触发钮在输入框右下角，标签为「主 ▸ 辅」形态
- [ ] 点开面板**只列支持图片的模型**
- [ ] 选中辅助模型 → 保存 → **重开面板值仍在**（配置真的落盘了）

### B2 · 路由生效

- [ ] 配好辅助模型后**拖入图片** → 状态行显示「图片将由「X」处理」
- [ ] 发送**纯文本**消息 → 模型选择器**不被切换**（`keep` 路径不抖动配置）

### B3 · ★ 纯文本主模型仍可传图（本线的硬契约）

- [ ] 把**主模型切到不支持图片的模型**
- [ ] 发送一条**带图**的消息
- [ ] **确认它发得出去**
- [ ] **打开模型回复，确认它真的读到了图里的内容**（不是"看起来发出去了"）
      —— 这一条是「不是静默丢图」的唯一判据

### B4 · 失效信号

- [ ] 在别处（官方模型设置页）改动模型 → 回到本线面板，**不显示陈旧值**
